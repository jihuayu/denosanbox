# Policy-mediated HTTP

`HttpConnector` is an explicit Rust host transport, not a raw socket capability. Each request authorizes its canonical DNS hostname and destination port **before DNS**, checks every returned address against `NetworkRules`, and pins those addresses on the connection while retaining the original HTTPS hostname for TLS/SNI and certificate verification. The connected peer must match a pinned address. Every redirect is resolved and authorized again; HTTPS downgrades are denied and authorization/cookie headers are stripped when the origin changes. Lifecycle/install scripts and native execution are unrelated and remain disabled.

Limits cover request body bytes across redirects, response body bytes, header count/bytes, redirect depth, DNS answer count, and total request time. Streaming chunks are checked before retaining them. TLS certificate verification stays enabled, with native roots and configured CA paths. Transport errors return fixed categories without URLs, headers, response bodies, resolver details or credentials.

Call `execute_with_policy` with a trusted policy provider for live narrowing, a host-owned cancellation token, and the inherited remaining deadline. Plain `execute` uses an immutable policy snapshot. Cancellation is polled every 5 ms; the request future is dropped and late results are discarded. Narrowing rechecks stop later admissions and response consumption; an already admitted request may have transmitted bytes before narrowing/cancellation is observed. Neither cancellation nor timeout rolls back remote side effects. Native system DNS may not cooperate with cancellation: at most four lookup threads are admitted globally, and their permits and per-connector accounting remain owned until they exit. Hosts must include `pending_resolutions()` in incomplete-close diagnostics. This is not a hard process-memory or OS-isolation guarantee.

HTTP forward proxies can resolve a peer different from the addresses checked by the host. If the inherited environment requires a proxy for a destination, the transport returns `unsupported_proxy` before DNS and does not bypass the proxy. Destinations already excluded by inherited `NO_PROXY` use normal client routing. No proxy variables are unset, no broad `no_proxy()` override is used, and TLS verification is never disabled. Public HTTP(S) egress therefore remains unavailable in a proxy-required deployment until a trusted pinning-aware proxy transport is supplied. There is no silent sidecar or weaker fallback.

Supported methods are GET/HEAD/POST/PUT/PATCH/DELETE/OPTIONS. GET/HEAD request bodies, IP-literal URLs, URL credentials/fragments, transport-control headers, WebSocket upgrades and raw sockets are rejected. Header values are not a complete browser Fetch/Headers implementation; response headers use a string map, no cookie jar is maintained, and compressed bodies are returned as bounded raw bytes.

Run `cargo test --manifest-path core/connectors/Cargo.toml` and `cargo clippy --manifest-path core/connectors/Cargo.toml --all-targets -- -D warnings`. Nine deterministic tests cover real loopback HTTP with explicit private grants, default denial, redirect port checks/credential stripping, byte limits, cancellation/deadlines, live narrowing, pre-DNS authorization and rebinding answer changes. A configured-proxy test checks the fail-closed gate without any public request. No external network, proxy or public TLS success is claimed by these tests.
